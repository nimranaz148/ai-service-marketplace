## 1. Purpose & scope

Rebuild the public marketing surface: the home page `/` as a cinematic, narrative-led GSAP experience, plus a visual-only restyle of the four unauthenticated auth-page shells so the whole logged-out surface reads as one system.

The current `/` is template-derived (Catalis): PKR 3,500/8,500/25,000 subscription tiers that don't fit a pay-per-booking marketplace, a 522-LOC 3D coverflow of fabricated artisans, and hero copy full of unverifiable claims ("100% Biometric Pass", "Guaranteed Artisan Escrow Hold", "Live GPS Beacon Tracking", "Bank / Raast Instant Settlement"). This phase replaces it with honest copy for the real product and a scroll experience that *shows* how the product works.

### In scope

1. **`/` full rebuild** — new nav + hero + 9 sections + footer on the dark `.theme-marketing` surface, with Approach A scroll (Lenis + GSAP ScrollTrigger). ~70% narrative-led (2 pinned/scrubbed story beats), ~30% polished reveals.
2. **Auth-page marketing chrome** — `/login`, `/signup`, `/provider/login`, `/admin/login`: wrap in `data-theme="marketing"`, replace ad-hoc dark hexes + glow/blob decoration with marketing tokens, keep **all** form logic, `useAuth` calls, routes, and field structure exactly as-is. Visual only.
3. **`--accent-strong` token** — resolves the parked Phase 0 contrast residual (white-on-ember primary-button label at 3.86:1). Add `--accent-strong: #C24A1E` (ember-600, ~4.9:1 on white) and point `--primary` at it; `--accent` (#DE5527) stays for non-text accent use (nav active, focus ring, tints, the ember spotlight). Mirror into `tokens.ts` (parity-guarded).

### Out of scope (later phases)

| Deferred | Phase |
|---|---|

| Conversational agent backend, real streamed events | 2 |

## 2. Success criteria

1. `/` renders the section arc in §5 on the `.theme-marketing` surface. No hardcoded hex; all colour/type/space via tokens.
2. Lenis smooth-scroll is active on `/` only, synced to GSAP ScrollTrigger, in one client boundary. It is **off** under `prefers-reduced-motion`.
3. Two pinned scrubbed narrative beats exist: **"Watch the agent work"** and the **trade-strip**. Under `prefers-reduced-motion` both un-pin and render their end state statically; scrubbed reveals become opacity-only.
4. Every other section animates via a shared `useScrollScene` hook — measured reveals/parallax/counter tweens, nothing decorative. The Phase 0 anti-slop rules (no blob-glow, no glow shadows, no emoji chrome, no fabricated metrics, no over-claiming) hold on every section.
5. Copy is honest: the product is described as it is (AI dispatch of vetted local AC/plumbing/electrical/cleaning/tutoring help via Roman Urdu or English chat and voice, across Islamabad / Karachi / Lahore, priced per job). No biometric-%, escrow-guarantee, GPS-beacon, or Raast-settlement claims unless they are actually real (they are not).
6. The pricing section is a single honest "how pricing works" block — per job, no subscription, rate shown before you confirm. The 3-tier subscription grid is gone.
7. The four auth pages render on the marketing surface with **zero** change to their form fields, submit handlers, `useAuth` calls, redirects, or routes. `git diff` on those files shows only className / wrapper / decoration changes.
8. `--accent-strong` exists in `globals.css` + `tokens.ts` (parity test green); `--primary` points at it; a contrast assertion covers `--accent-ink` on `--accent-strong` ≥ 4.5.
9. Verification: `npx tsc --noEmit` 0 · `npm run test` all pass (incl. new: `/` render smoke, `useScrollScene` reduced-motion behaviour, the auth-chrome "logic untouched" guard) · `npm run build` PASS · axe no serious/critical on `/` and one auth page · manual browser pass confirms the scroll, the two pinned beats, reduced-motion fallback, and no CLS on the hero.
10. Perf: the marketing route's added client JS (Lenis + GSAP + ScrollTrigger + section timelines) is code-split to `/` and stays within ~90 KB gzip over the shared baseline. No client data fetch on `/`. Hero headline + sub are server-rendered (no layout shift; fonts already `display: swap`, self-hosted).

## 3. Approach (chosen: A)

**A — Lenis smooth-scroll + GSAP ScrollTrigger, one timeline module per section.**

- `lib/motion/lenis.ts` — a client-only Lenis singleton, `raf`-driven, `ScrollTrigger.update` on Lenis `scroll`, `ScrollTrigger.scrollerProxy` wired so pins work. Disabled (and not instantiated) when `prefersReducedMotion()`.
- `lib/motion/use-scroll-scene.ts` — `useScrollScene(ref, build)` hook: on mount (client, not reduced-motion), calls `build(gsap, ScrollTrigger, el)` to create a scoped timeline/trigger; cleans up on unmount; no-ops under reduced-motion (the section renders its static end state).
- `components/marketing/*` — one component per section, each owning its own scene via the hook. `app/page.tsx` is a thin server component that composes them inside a `<MarketingRoot>` client wrapper (sets `data-theme="marketing"`, mounts Lenis, provides the GSAP context).
- Rejected: **B** (native scroll, no Lenis) — the narrative scrub feel is the point and Lenis is the standard pairing; **C** (framer `useScroll` for reveals) — two scroll systems that fight on a pinned page, and contradicts Phase 0 §8 (GSAP is *the* marketing motion system).

## 7. Motion system detail

- **Registration:** `getGsap()` (Phase 0) registers `ScrollTrigger` + `SplitText`. `MarketingRoot` calls it once and creates a `gsap.context()` scoped to the page root so all section timelines are reverted together on unmount.
- **Lenis:** instantiated in `MarketingRoot`'s effect only when `!prefersReducedMotion()`. `lerp ~0.1`, `wheelMultiplier 1`, no smooth-touch (native on mobile). `requestAnimationFrame` loop drives `lenis.raf`; `lenis.on('scroll', ScrollTrigger.update)`; `ScrollTrigger.scrollerProxy(document.documentElement, {...})` + `ScrollTrigger.defaults({ scroller: document.documentElement })`. Killed on unmount.
- **`useScrollScene(ref, build)`:** guards `typeof window`, `ref.current`, `!prefersReducedMotion()`. Calls `build(gsap, ScrollTrigger, ref.current)` inside the page `gsap.context`. Returns nothing. Under reduced-motion it does nothing and the section's JSX must already be in its resting/end visual state (no `opacity:0` defaults in CSS — initial hidden states are set by GSAP `.from()` / `.set()` only, so no-JS and reduced-motion both show content).
- **Pinned beats:** `pin: true`, `scrub: 1`, `anticipatePin: 1`, `end: "+=<n>"` sized to content. `AgentBeat` end state = the confirmed-booking card; `TradesCoverage` end state = strip resting at its final X. Both provide a `data-reduced` static layout branch.
- **Reveals:** a single shared easing (`--ease-out` value) and duration band (≤ 0.6s for marketing reveals, ≤ 0.26s for any in-view micro-move), `start: "top 80%"`, `once: true` for content reveals (no replay on scroll-up), `toggleActions` only where a two-way effect is intentional (nav bg).
- **Counters:** `gsap.to({v:0}, { v: target, snap:{v:1}, onUpdate })` — only for the genuinely-numeric proof stats; never for invented figures.
- Global `prefers-reduced-motion` CSS from Phase 0 already zeroes transitions; this phase additionally ensures no pinned section traps scroll and Lenis never mounts.

## 8. Content rules

- All strings live in `lib/marketing/copy.ts` (typed, grouped by section). One place to iterate tone or add Urdu-script variants later.
- Bilingual voice is deliberate and consistent: headline + CTAs carry Roman Urdu warmth ("Bol do", "Ghar ka masla", "Pehli booking abhi karein"); explanatory body is plain English. Not word-salad code-switching mid-sentence.
- No claim without backing. Allowed: "verified providers" (they're vetted in the product model), city names, trade names, "per job pricing", "type or speak", "see price before you confirm". Not allowed: percentages, "biometric", "escrow", "GPS", "Raast", "instant", "guaranteed", counts we can't source.
- Proof quotes: until real ones exist, 2 short illustrative quotes with a visible "illustrative" footnote. First name + area only.

## 10. Assets & performance

- **No external images / stock photography** (can't source reliably; also a perf and licensing liability). Visual interest comes from: type, the `.theme-marketing` palette, one inline-SVG `DispatchMotif`, the live Phase 0 agent primitives in `AgentBeat`, restrained craft-colour material touches, and motion. If a real photo library appears later it slots into `Hero` / `Proof` behind `next/image`.
- **Code-split:** `MarketingRoot` and all `components/marketing/*` are client components loaded only on `/`. Lenis + the section timelines do not enter the shared bundle. `next build` route table must show `/` first-load JS within ~90 KB gzip of the current baseline.
- **LCP:** the hero headline + sub render server-side inside `MarketingRoot`'s children (client wrapper, server children where possible) with no `opacity:0` initial CSS — GSAP sets the hidden state after hydration, so first paint shows text. Fonts are self-hosted `display: swap` (Phase 0). No CLS from the nav (fixed height) or the pinned sections (they reserve their `end` height).
- **Mobile:** pinned beats degrade gracefully — on `< 768px` the two pinned sections un-pin and become vertical staged reveals (the scrub story still reads, just without the pin). Lenis smooth-touch off (native).

## 11. Accessibility

- `prefers-reduced-motion`: Lenis never mounts; `useScrollScene` no-ops; pinned sections render static end states; all content visible without JS.
- The pinned `AgentBeat` is not a scroll trap: it releases at its `end`; keyboard users tabbing through reach a normal document below it.
- `MarketingNav` fully keyboard operable; visible `--focus-ring` on every interactive element; skip-to-content link.
- `request-box` and footer newsletter are real `<label>`ed inputs even though non-functional (submit → `/signup`); no dead `<div onClick>`.
- Headings nest `h1` (hero) → `h2` (each section) → `h3` (sub-items). One `h1` per page.
- Colour: AA for all text (the `--accent-strong` change makes primary-button labels pass; verify hero/section text on `--warm-950` ≥ 4.5).
- axe: no serious/critical on `/` and on `/login` in the verification run.
